# Agent hub protocol

The orchestrator plans and audits; workers build; verifiers check. Nobody grades their own work. Every command is `node .agent-hub/hub.mjs <command> [args]` from the repo root (or set `AGENT_ID`). State lives in `.agent-hub/events.jsonl`; `BOARD.md` is the readable view, regenerated by every command.

## Roles

| Role | Who | Does | Never |
|---|---|---|---|
| Orchestrator | one agent (main Claude session) | Splits work into tasks, writes briefs in `.agent-hub/tasks/`, assigns, reviews diffs and reports, accepts or rejects, commits | Edits source files itself. Accepts work without reading the diff. |
| Worker | `builder-N`, or an external agent | Claims an assigned task, follows its brief, proves the result, reports with `done` | Works without a claim, edits outside the claim, commits, verifies its own task |
| Verifier | `verifier-N` | Re-runs the proof, runs gates, compares with the source, writes a report, `verify --ok` or `--fail` | Fixes code. Verifies a task it did. |

## Lifecycle

```
OPEN → ASSIGNED → CLAIMED → REVIEW → (VERIFIED) → ACCEPTED
                     ↑         │            │
                     └── REWORK ←───────────┘   (verify --fail or reject)
```

Since D-010 there is no verifier step by default: builders prove build, lint, gen-registry (if applicable), gates, and a clean git status (no browser checks), and the orchestrator reviews and accepts. A dependency counts as met once it is built (REVIEW or later) unless the task is `--strict on`.

## Worker loop

1. `join --role worker --tool claude --note "focus"`, then `next` and `inbox`.
2. Read the brief `.agent-hub/tasks/<TASK>.md`. It lists what to load. Load nothing else.
3. `claim <TASK> --files <every file you will write>`. Exit 3 = conflict: stop and `say` to the orchestrator.
4. Need another file? `files <TASK> --add <path>` before touching it.
5. `progress <TASK> --note "..."` at milestones, `heartbeat` at least every 20 minutes. Silent for 45 minutes = STALE.
6. Stuck on a decision or dependency: `block <TASK> --note "what you need"` and stop.
7. Finish: run every "Done when" check, then `done <TASK> --summary "..." --files a,b --verify "cmd -> result"`.
8. `leave` when you have nothing assigned.

## Verifier loop

1. `join --role verifier`, `next` lists tasks waiting for verification.
2. Read the changelog entry and the brief, inspect `git diff -- <files>` and new files.
3. Re-run the worker's proof, then the gates for that phase. Write the report.
4. `verify <TASK> --ok|--fail --note "what you checked" --report <path>`.

## Orchestrator loop

1. `join --role orchestrator --tool claude`. Read `docs/HANDOFF.md`, `status`, `inbox`.
2. Plan: create tasks with deps and scope (`add`), write each brief from the template, `assign`.
3. Dispatch: spawn the matching executor with its agent id and task id, or hand the task to an external agent.
4. Audit every REVIEW or VERIFIED task: read the diff, spot-check one claim in the proof yourself, check scope was respected.
5. `accept` (then update the handoff, commit only the task's files) or `reject --note "fix list"`.
6. End of session: rewrite `docs/HANDOFF.md`, `leave`.

## Shared-tree safety

1. Only the orchestrator stages and commits, file by file from the accepted task (never `git add -A` while workers are active).
2. Nobody runs `git stash`, `git checkout -- <file>`, `git restore`, `git reset --hard`, `git clean`, or switches branches.
3. No repo-wide formatters or codemods.
4. Dev servers: each agent claims its port as a file entry `port:<n>` in its claim and stops the process when done.
5. Out-of-scope problem found: do not fix it, `say` it so it becomes a task.

## Messages

`say "TASK: text" [--to id]`. Questions for the human start with `HUMAN:` and are relayed by the orchestrator.
